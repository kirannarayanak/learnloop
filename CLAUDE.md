# Working notes for Claude on this repo

## What this is
LearnLoop: a pipeline that turns arbitrary sources into verified learning paths, plus a
PWA to learn from them. Read `docs/01-vision.md` and `docs/04-content-pipeline.md` before
making design decisions — the docs are current and are the source of truth for intent.

## Stack
Next.js (PWA) · Postgres + pgvector via Supabase · Cloudflare Pages/Workers + R2 ·
FSRS for scheduling. Jobs are rows in `generation_jobs`, leased via `locked_until`.
No external queue.

**Models are provider-agnostic.** No pipeline stage names a vendor — `engine/providers/routing.ts`
is the only place a model choice exists. Gemini is the primary provider (long context for
whole-syllabus ingest, native PDF/video, strong Indic languages); the verify stage is routed
to a different family on purpose. Embeddings are always an open model.

## Rules that are not negotiable
- **No LLM call in a learner's request path for content.** Content is generated by workers,
  verified, and served as cached rows. The only live model calls are tutor turns, which are
  capped per user. Violating this breaks the economics in `docs/05-economics.md`.
- **Every generated claim cites a source span.** `lesson_sources.quote`. No citation → no publish.
- **High-risk domains require `verify_state = 'human_approved'`** to publish. Enforce in the
  publish query, never by convention. If you touch that query, there must be a test.
- **`attempts` is append-only.** Never update or delete. Offline sync and calibration both
  depend on it. Use the `client_id` idempotency key.
- **The verifier must be a different model family than the drafter.** A model checking its
  own output shares its own blind spots and will approve its own hallucinations.
  `assertVerifierIndependence()` throws at startup; don't catch it, fix the routing.
- **Never name a model outside `engine/providers/routing.ts`.** Stages take a `ModelRef`.
- **Multi-tenant isolation is RLS, not `WHERE org_id = ?`.** Policies in `db/policies.sql`.
- **`sources.license` null ⇒ cite and link only, never reproduce.** Legal gate, in code.
- **Never award points for correct answers.** Points reward effort and consistency only.
  Rewarding correctness punishes struggling learners and drives avoidance of hard material
  (`docs/10-motivation.md` finding 5). There is a test that fails if a correctness kind appears.
- **No global leaderboard, ever.** Macro leaderboards demonstrably harm lower performers.
  Small bucketed leagues (~30), opt-in, personal-best by default (finding 3).
- **Mastery gating is SOFT.** Mastery gates *credit*, never *access* — hard-locking content
  reduces completion and would fight our own wave-0 exit gate (finding 2). `skill_readiness`
  is an advisory view; it must not block anything.
- **Streak freezes are earned and auto-applied, never sold.** Monetising a motivation
  mechanic corrupts it, and protection outperforms reward anyway (finding 4).

## Cost discipline
- Batch API for every generation pass; nothing in the pipeline is latency-sensitive.
- Put the stable source-material prefix before the last `cache_control` breakpoint; keep the
  volatile per-item parts after it. Workers must log `usage.cache_read_input_tokens` and warn
  when it's 0 — a silent cache miss is a ~10x cost regression.
- Record `cost_usd` on every job and every cached generation. Cost per path is the metric the
  whole business model rests on.

## Conventions
- TypeScript, strict. `engine/` must not import from `web/` — it runs as a worker and a CLI.
- SQL migrations are forward-only, numbered, one concern each.
- Skills are phrased as observable "can do X" statements. If you can't write a question for
  it, it isn't a skill — don't create the row.
- The prerequisite graph must stay acyclic. `engine/graph/validate.ts` fails the job on a cycle.

## Running it
npm workspaces; run everything from the repo root.
```
npm install
npm run dev           # seeds content, then serves the app on :3310
npm test              # engine suite: node --test, no test framework dependency
npm run typecheck     # strict tsc across both workspaces
npm run seed          # re-run the pipeline, rewrite web/lib/seed.json
```
`web/lib/seed.json` is generated by `npm run seed` — it is the wave-0 stand-in for
Postgres. Edit the pipeline or the sources, not the JSON.
Node runs the `.ts` files directly via native type stripping, so **imports use `.ts`
extensions** and TS syntax needing transformation is unavailable — no enums, no namespaces,
no constructor parameter properties. Write explicit fields instead.
