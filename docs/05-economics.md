# 05 — Economics: how this stays free for learners and still pays for itself

All model prices are Anthropic first-party list rates as of 2026-10. Re-verify before
quoting these to anyone. Batch API = 50% off, used for all non-urgent generation.

| Stage | Model | Input $/MTok | Output $/MTok |
| --- | --- | --- | --- |
| graph, ingest | Gemini 3.1 Pro | $2.00 | $12.00 |
| draft, translate, tutor | Gemini 3.8 Flash | ~$0.30 | ~$2.50 |
| **verify** | **Claude Opus 5** | $5.00 | $25.00 |
| embed | open model, self-run | — | — |

Flash pricing was not confirmed when this was written — it is a placeholder of the right
order of magnitude, not a quote. `assertPricesConfigured()` warns about a missing price but
cannot catch a wrong one, so re-check before quoting any of this to anyone.

Gemini caches **implicitly** on current models: a request reusing a prefix you have sent
before gets roughly 90% off those tokens, with nothing to manage. That is why the pipeline
is so careful to put the source material in a byte-identical prefix — the discount is
automatic, but only if the bytes actually match.

## The one number the whole business rests on

**Generate once, serve forever.** A learning path is generated by a worker, verified, and
written to Postgres. Every subsequent learner reads rows. So:

> **cost per path ≈ $0.40, paid once, amortised across every learner who ever takes it.**

Worked estimate for one path of 8 skills from a ~15k-token source:

| Pass | Model | Est. cost |
| --- | --- | --- |
| Skill-graph + path structure | Gemini 3.1 Pro | $0.07 |
| 8 lesson drafts (source cached after the first) | Gemini 3.8 Flash | $0.09 |
| 8 verifications | Claude Opus 5 | **$0.24** |
| **Total** | | **≈ $0.40** |

**Verification is now ~60% of the cost of a path**, because it runs on the most expensive
model in the stack while drafting runs on one of the cheapest. That is the right shape, not
a problem to optimise away: verification is ~10% of tokens and 100% of the safety gate
(`docs/09-model-strategy.md`). If the bill ever needs cutting, batch the verification pass
before moving it to a cheaper model — and only then with an eval set proving quality held.

So **10,000 verified paths ≈ $4,000, one time.** That is a broad curriculum across many
domains for the price of a used car. Serving it to the ten-thousandth learner costs a
database read. *This* is why the engine shape beats a course catalogue — and why "all
domains" is reachable without a thousand-person content team.

Levers that make the above real, not optimistic:
- **Prompt caching** on the source-material prefix across all lessons from one source
  (cache reads ≈ 10% of input price). Verify with `usage.cache_read_input_tokens` — if it's
  zero across repeated calls, something volatile is leaking into the prefix.
- **Batch API** for every generation pass. Nothing about path generation is latency-sensitive.
- **Model ladder.** A cheap model drafts, an expensive one from a different family
  verifies. Never one model for everything, and never the same family for both.
- **App-level content cache** keyed on `hash(source_version + skill_spec + prompt_version)`.
  Re-runs are free until a prompt or a source actually changes.

## The variable cost: live tutor turns

The only per-learner recurring cost. One turn ≈ 3k input (mostly cache reads, since the
lesson context is a stable prefix) + ~400 output on Haiku 4.5:

> **≈ $0.002 per tutor turn** on Gemini Flash with the lesson context cached.

| Tier | Tutor cap | Inference cost / user / month |
| --- | --- | --- |
| Free | 20 turns/mo | **~$0.06** |
| Pro | ~300 turns/mo soft cap | ~$0.90 |

**The free-tier cap is not optional.** Uncapped, 100k free actives at 50 turns/month is
~$15k/month and it kills the project. Capped at 20, the same 100k users cost ~$6k/month —
and crucially, *reading lessons and doing practice stays unlimited and free*, because those
cost a database read. The cap falls only on the one expensive feature. Show remaining turns
in the UI; let the cap reset monthly; let learners earn extra turns by reviewing content.

## Revenue

Learning content is **never** behind a paywall. We charge for tooling, cohorts, and proof.

**1. Pro — individuals.** Unlimited-ish tutor, generate your own paths from your own sources,
export/offline bundles, progress analytics, certificates.
Price **PPP-adjusted by country**, which is the whole point if this is for everyone:
~$5/mo US/EU, ~₹149/mo India, ~$2/mo across most of Africa and South Asia.
Target conversion 2–4% of monthly actives — not 10%; be honest.

**2. Institutions — the revenue engine.** Colleges, bootcamps, NGOs, employer L&D.
They point the engine at *their* syllabus and get cohort dashboards, mastery heatmaps,
assignment flows, SSO, and an admin audit trail.
~$2–5/seat/month (lower in low-income markets, higher for employer L&D).
A 500-seat college at $3/seat/mo = **$18k/year from one signature.** Five of those is a
sustainable company. **Validate this with five real conversations before building the
dashboard** — not with this spreadsheet.

**3. Verified assessments / credentials.** Employers pay per verified assessment; learners
never do. Open Badges + a public verification URL so the credential is checkable by anyone.

**4. Creator revenue share.** Experts publish and maintain paths; they take the majority
of Pro revenue attributable to their paths. This is how the catalogue reaches "all domains"
without us hiring for all domains.

**5. Grants and sponsorship.** Education-access funders, cloud credit programmes
(Cloudflare/Supabase/AWS have them), and an open donation page once the OSS core is public.
Treat grants as runway for wave 3 (offline + local languages), never as the business model.

## Sustainability check

Fixed infrastructure is ≈ $0 on free tiers through roughly the first 10k learners, and under
~$100/month past that. So the break-even question is only about inference:

> **1,000 Pro subscribers at a $5 blended price ≈ $5,000/month, which funds the free-tier
> tutor budget for ~80,000 free learners.**

That ratio — **1 payer sustains ~80 free learners** — is the number to put in front of a
funder, an institution, or a co-founder. It's also the number to re-measure every month,
because it's the first thing that will drift.
