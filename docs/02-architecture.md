# 02 — Architecture

Constraint from the start: **run on free tiers and open source until revenue exists.**
Every choice below is either OSS or has a free tier that covers the first ~10k learners,
and every one has a stated escape hatch so we never get hostage-taken by a vendor.

## Shape

```
                  ┌─────────────────────────────┐
  learner ──────▶ │  PWA (Next.js, offline-first)│  installable, works on 2G, works offline
                  └──────────────┬──────────────┘
                                 │  REST/RPC
                  ┌──────────────▼──────────────┐
                  │  API (Next.js routes / Hono) │  stateless, edge-deployable
                  └───┬──────────────┬──────────┘
                      │              │
          ┌───────────▼──┐   ┌───────▼───────────────┐
          │ Postgres     │   │ Generation workers     │  async, never in request path
          │ + pgvector   │   │ (ingest → draft →      │
          │ (Supabase)   │   │  verify → publish)     │
          └───────┬──────┘   └───────┬───────────────┘
                  │                  │
            ┌─────▼─────┐      ┌─────▼──────────┐
            │ R2 / S3   │      │ Claude API     │  Haiku bulk · Sonnet hard · Batch 50% off
            │ media +   │      └────────────────┘
            │ offline   │
            │ bundles   │
            └───────────┘
```

**The single most important architectural rule:** no LLM call ever happens in a learner's
critical path for *content*. Content is generated by workers, verified, written to Postgres,
and served as plain cached rows. The only live model calls are the optional tutor turns.
This is what makes the free tier survivable (see `05-economics.md`).

## Stack, with reasons and escape hatches

| --- | --- | --- | --- |

| Object storage | **Cloudflare R2** (10GB free, **zero egress**) | Offline bundles and images are egress-heavy; S3 egress would bankrupt us | Supabase Storage; Backblaze B2 |

## Offline-first, concretely
This is a feature, not a nice-to-have — it's what makes wave 3 possible, and it also makes
the app feel instant for everyone else.

- Service worker caches the app shell + the learner's **active path** (lessons + exercises).
- `IndexedDB` holds lesson content, the exercise bank, and a **write-ahead queue of attempts**.
- Attempts and FSRS state sync when connectivity returns; conflict rule is *last-write-wins
  per (user, exercise, attempt_id)* — attempts are append-only, so there is nothing to merge.
- A path bundle is a signed tarball on R2, typically **under 2MB of text** for a 12-lesson
  path. Images are lazy and optional. Nothing requires video.
- Target: a usable session on a 2015-era Android phone over 2G.

## Monorepo layout
```
learnloop/
├── web/        Next.js PWA + API routes
├── engine/     ingest → draft → verify → publish pipeline (plain TS, runnable standalone)
├── db/         schema.sql, migrations, seed
└── docs/       this folder — the thinking, kept in the repo on purpose
```
`engine/` stays independent of `web/` so it can run as a worker, a CLI, or a cron job
without dragging a web framework along.

## Open source stance
Open-source the core under **AGPL-3.0**, keep the hosted cohort/org layer proprietary
(the standard "open core" split). AGPL specifically: it means a competitor can't take the
engine, host it closed, and outspend us on ads. It also buys trust and contributors —
which, for an education project asking to be believed, is worth more than the code.
